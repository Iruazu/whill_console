# ADR-0007: sam_infer は作らない（当面）。カメラは「見えること」に絞る

- 状態: 採択
- 日付: 2026-09-16
- Phase: 6

## 背景

実装計画書の Phase 6 には 3 つ目として `sam_infer`（uv 別プロセス、ZeroMQ）が
挙がっていた。しかし計画書に書いてあるのは**実行形態だけ**で、目的が無い。
既存スタック（`~/whill_lab0_ros2`）にも該当するものは無かった（#54）。

用途が決まらないと、モデル・速さ・入力・安全区分のどれも決められない。とくに
「結果を Nav2 に効かせるか」で性格が変わる。効かせるなら安全に関わり、
「後回し可の周辺機能」ではなくなる。

## 決定

**sam_infer は着手しない。** 用途が決まるまで凍結する。

代わりに、カメラについては**「画像が見えること」だけを充実させる**。推論は載せない。

ユーザの判断（2026-09-16）:

| 決めること | 回答 |
|---|---|
| 結果を誰が使うか | **具体的な用途が未確定。カメラ画像が見えればよい**（推論は要らない） |
| 速さ | 毎フレーム（＝ドライバが出すレートで見たい） |
| どこで動かすか | 実機PC |
| 何を切り出すか | まだ決めていない |

「速さ」「どこで動かすか」は、将来 sam_infer を作るときの前提として記録しておく。

## 根拠

- **目的の無い推論を先に作らない。** モデルと依存（GPU、ライセンス、numpy の版）を
  抱え込んだうえで、後から用途が決まって作り直すのが一番高くつく
- 「見るだけ」なら推論は要らない。**カメラ画像を実際に見られるようにするほうが先**
- 研究室PC は `nvidia-smi` が `Driver/library version mismatch`（2026-09-14 / 2026-09-16 とも）。
  GPU 推論を前提にするなら、まずドライバを揃えるところから
- 設計原則 2（3D 表示・解析は Foxglove に委譲）と同じ考え方。**自作する範囲を
  広げないほうが、実機復帰後に効く**

## 影響

- Phase 6 は camera（#52, #53）と tf（#51）で完了とする
- 画像のレート制限（`whill_gateway.image_publish_rate`）の既定を 1 Hz から
  ドライバの宣言レート（6 Hz）へ上げ、上限も実機の profile（最大 30 fps）まで
  広げる。画像は camera パネルを開いているあいだしか流れない（#52）ので、
  見ていない端末の帯域は増えない
- 用途が決まったら #54 を開き直し、実装の issue を切り直す。**このときやり直すのは
  決定であって、コードではない**（何も作っていないため）

## 却下した案

- **とりあえず SAM を動かして静止画で試す。** 目的が無いまま依存とモデルを
  抱え込む。「動いた」以上のことが言えず、次に何をすべきかも分からない
- **推論結果を Foxglove で見る前提で最小限だけ作る。** 見るだけなら推論そのものが
  要らないので、順序が逆
