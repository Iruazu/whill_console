# 止まるまでの時間（2026-09-19、mock）

Phase 7 の段 1 で使う道具（`whill measure stop`、#78）を、実機の前に mock で通したときの値。
**実機の値ではない。実機で測り直す前提の基準線。**

## 条件

- `whill run --robot cr2-01 --mode mock`（gateway は別建て、`ROS_DOMAIN_ID=171`、port 8799）
- `whill measure stop --repeats 3`（0.1 m/s で動かしてから止める）
- 測るのは **`/whill/controller/cmd_vel`（実ドライバが受ける口）がゼロになるまで**

## 結果

| 止め方 | 回数 | 中央値 | 最大 | ゼロにならなかった回数 |
|---|---|---|---|---|
| E-STOP | 3 | 30 ms | 49 ms | 0 |
| ハートビート断 | 3 | 430 ms | 475 ms | 0 |

## 読み方

- **ハートビート断の 430 ms は設定どおり。** `manual_heartbeat_timeout` は 0.5 s で、
  測り始めは「最後に指令を送った時刻」なので、0.5 s より少し短いところでゼロになる
- E-STOP の 30 ms は WebSocket の往復 + gateway の処理。**mock なので下流は即座に反映する。**
  実機は twist_mux → velocity_smoother を通るので伸びる（K7 の順序の違いもある）
- mock の車体は「速度を積算するだけ」なので、**実際に車輪が止まるまでの時間は測っていない**。
  実機では指令がゼロになってからの惰性も見る（段 1 で人が目視する）

## 実機で見ること（段 1）

- 車輪を浮かせた状態で同じコマンドを打つ
- **ゼロにならない回が 1 回でもあれば、そこで中止**（`whill measure stop` は終了コード 1 で知らせる）
- Wi-Fi を物理的に切る形でも同じことを確かめる（この道具は WebSocket を維持したまま黙る形なので、
  切断そのものは別に試す）
